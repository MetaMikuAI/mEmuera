# 构建与发布

- 推送分支、提交 PR：编译四种桌面版本和两种 APK，保留产物 14 天。
- 推送 `v版本号` 标签：重新执行全部检查，通过后自动发布 GitHub Release。
- Actions 页面可手动构建，但不会创建 Release。

版本只修改根目录 `Directory.Build.props` 的 `Version`。标签必须完全对应，例如 `0.1.0` 对应 `v0.1.0`。次版本和修订号须小于 1000。

## 下载文件

以 0.1.0 为例，每次发布六个文件，不另加压缩包或校验文件：

| 文件 | 平台 |
| --- | --- |
| `mEmuera-0.1.0-win-x64.exe` | Windows x64 |
| `mEmuera-0.1.0-linux-x64` | Linux x64 |
| `mEmuera-0.1.0-osx-arm64` | Apple Silicon Mac |
| `mEmuera-0.1.0-osx-x64` | Intel Mac |
| `mEmuera-0.1.0-android-arm64.apk` | Android 真机 |
| `mEmuera-0.1.0-android-x64.apk` | Android x64 模拟器 |

桌面版自带 .NET，下载后在终端运行，并传入 `--game "游戏目录"`；Linux/macOS 首次运行先 `chmod +x 文件名`。原生库会自动解压到运行时缓存。桌面程序未做 Windows 代码签名或 Apple 公证。游戏文件、音频播放器不随程序附带。

普通构建 APK 文件名带 `-test`，使用测试签名；标签构建使用固定发布签名。两种签名不能相互覆盖安装。Android 游戏和存档均位于 `/sdcard/emuera/`。

仓库 Actions Secrets 需配置 `ANDROID_KEYSTORE_BASE64`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`。请另行备份密钥，避免丢失后无法覆盖升级。

## 发布步骤

修改版本并提交，推送分支后，在同一提交上创建并推送标签：

```bash
git tag v0.1.0
git push origin v0.1.0
```

CI 检查版本并编译产物；进入游戏、桌面交互及设备兼容性由实机验证。
